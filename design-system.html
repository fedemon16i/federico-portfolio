Input variants

Every interactive input documents four states. Never rely on browser defaults alone — always define focus ring, error styling, and disabled appearance explicitly.

Default
Focused
Error
Enter a valid email address

Component states

UI state spec

Every data-connected component must handle all four states. Empty state is the most commonly omitted.

Loading

Skeleton pulse or spinner at var(--accent) opacity .6. Never show partial/stale data. Announce to screen readers via aria-live="polite".

Error

Red border (#ef4444) + inline error message below the field. Never silent failure. Always provide a retry path.

Empty

Explicit empty state: muted icon + label + optional call to action. A blank container is never acceptable — it reads as broken.

Disabled

opacity: 0.4 · cursor: not-allowed. No hover transforms. Must still meet 3:1 contrast at reduced opacity.

What drives beats

State machine

idle → typing → holding → device → next. runId guards stale timeouts. prefers-reduced-motion respected.

CSS + timers

Timing (visitors)

Playback pace

Narrative typewriter + beat holds tuned for people browsing a portfolio — not a product demo marathon.

A · Balanced (shipped)

Type ~26–28ms/char · beat holds ~0.5–0.9s median · interactions responsive. Best default for recruiters.

B · Snappy

~15% faster narrative · shorter holds. Use if analytics show drop-off mid-player.

Player states

Beat lifecycle states

Each beat cycles through idle → typing → hold → done before calling done(). runId guards stale callbacks across replays.

idle
between beats · win cleared · cursor hidden · cap faded out
typing
typeTitle() running · ~26ms/char · em words get accent color inline
hold
text complete · cap visible · pause ~1.1s before next action
done
beat finished · loops to next beat (or beat 01 after 08) · prefers-reduced-motion stops autoplay

Scale

Match duration to the perceived weight of the change. Faster for micro-feedback; slower for layout and narrative beats.

normal300msMost CSS transitions — borders, backgrounds

Stagger

List entrance

Cards enter with a 60ms stagger between siblings. Base delay: 100ms. Cap at 6 items — beyond that the last card feels too slow.

children.forEach((el, i) => { el.style.animationDelay = (100 + i * 60) + 'ms'; el.classList.add('animate__fadeInUp'); }); 6 items max stagger → last card at 460ms total Reduced motion → skip delay, keep opacity-only fade

Reduced motion

Policy

The universal selector in shared.css collapses all transitions to 0.01ms. No per-component prefers-reduced-motion blocks needed — it's already covered globally.

@media (prefers-reduced-motion: reduce) { *, *::before, *::after { transition-duration: .01ms !important; animation-duration: .01ms !important; animation-iteration-count: 1 !important; } } Player autoplay stops when prefers-reduced-motion is set — checked at init.

Canon

Consistency rules

1 · Shell

--max 920 · --pad · site-nav · theme toggle on every page. No full-bleed content.

2 · Players

Same unit/phone contract — only the plugin (BEATS, applyAction, case UI) changes per project.

3 · Accents

Local color only. Always define a light pair at ≥4.5:1 on #f7f5f2. No dark-green-on-dark combos.

4 · Type

Shared --h1/--h2 clamps, shared font families. No one-off hero type sizes. Min weight: 400 body, 600 headers.

5 · Motion

Skill card hover = reference for project cards. Growing elements always use --ease-out-back (with bounce). Pointerleave debounce 70ms to prevent cascade.

6 · Width

No 960px column. No double padding. No nested narrower container. Never horizontal scroll on body.

7 · Cards at rest

Solid tint only. Gradient + glow appears ONLY on hover — never as resting state.

8 · Accessibility

Skip link first child of body. Every img has alt. Nav has full ARIA. No focus ring suppression.

Governance

Who owns what

Before touching any shared file, understand what it affects across the whole site.

assets/shared.css

Color tokens, spacing scale, 3D card system, wireframe kit. All components reference variables — never hardcode hex in layout.

assets/demo-kit.js

Animation primitives: tilt3D, cursor, funnel, segmentTable, dualPath. Consumed by all players. No breaking API changes without updating all consumers.

assets/main.js

Nav dropdown, keyboard nav, mobile menu, scroll animations. Site-wide — every change must be tested on all pages.

Per-page inline CSS

Only project-specific overrides: accent value, hero layout, custom sections. If a pattern repeats on 2+ pages, move it to shared.css.

Player files

Each player owns its plugin CSS. Shell chrome (stage arrows, buttons, capbar) must follow the unified light/dark spec — Customs ES is the reference.

New components

Grep class name before using it. Verify it doesn't land inside the pointer:fine block. Test at 320/375/768/1024/1440/1920px widths before shipping.

Text / border

Text must not touch its container border. Minimum 8px padding on all sides.

Heights

Sibling cards must match height (use align-items: stretch on the grid parent).

Animation

New transitions: has bounce? respects prefers-reduced-motion? has pointerleave debounce if size-changing?

Width scan

Test at 320 / 375 / 768 / 1024 / 1440 / 1920px. No overflow-x on body at any width.

Class collisions

Grep new class names before using them. Duplicate class names with different rules = silent cascade conflict.
