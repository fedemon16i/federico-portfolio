System · Viewport

Stages, aspect locks, 3D

Height budget first. Stages use --stage-h: min(520px, 100vh - 220px) so short notebook viewports shrink the surface instead of clipping UI.

Aspect locks. Phone mocks stay 9 / 19.5; web frames 16 / 10. Scale with max-height/max-width — never stretch.

Container queries. Hosts declare container-type: size so children adapt to the stage box, not only the viewport.

Three.js. setPixelRatio(min(dpr, 1.75–2)), antialias on, resize re-applies DPR. Mini map cards use the same path at 1.75.

Device policy. Mobile demos stay mobile chrome; web stays web. Do not auto-swap layouts mid-animation.

Framework

Stage language (v4.1)

One law for Home skill modals, EY Product Intelligence, Blockchains Demo and Process, and every future case player.

  • Measure — content max 920px (Blockchains is the reference).
  • Player — chrome ~30% + one stage; mobile stacks with explicit stage height.
  • Beats — narrative owns full stage → UI appears as a window → caption is gradient/blur only.
  • Fit — scale mock so ~90% of UI components stay visible (no crop, not transparency).
  • Phone — aspect-ratio 9/19.5; size from host; entire device visible.

See docs/FRAMEWORK-v4.md and framework-playground.html.
