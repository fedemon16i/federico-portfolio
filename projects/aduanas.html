02

The problem

A vehicle does not cross the border with a single click.

Customs operations in El Salvador faced a critical gap: the administrative process (ARIVU document creation) and the physical control process (boarding pass validation at the border) were disconnected. Information entered in the office did not reliably reach the field agent's hands.

This meant duplicate data entry, lost authorizations, and no audit trail when a vehicle was rejected at the checkpoint. Four actors — importer, customs agent, driver, and control officer — each needed a different view of the same truth.

03

Four actors, one operation

Each actor needs a distinct view of the same truth. The system prevents information from getting lost between administrative management and physical control.

IM

Importador

Requests authorization and gathers vehicle, transport, and commercial operation data.

Goal: initiate the procedure
AA

Agente aduanero

Completes and reviews the ARIVU on behalf of the importer; fixes observations before submission.

Goal: create a correct record
CM

Conductor

Transports the vehicle and presents the boarding pass at the control point.

Goal: accredit entry
CA

Control de Aduanas

Verifies identity, selectivity, and documentation before authorizing the next movement.

Goal: decide with evidence
04

How I worked

01

Foundation system

Defined semantic tokens (color, spacing, radius, typography) that map to PrimeNG components. No hardcoded values per screen — every style resolves to a token.

02

Document flow

Built the ARIVU creation flow as a 4-step stepper: selection → form → review → success. Pre-filled realistic data so stakeholders see the end state immediately.

03

Operational flow

Designed the boarding pass as a condensed, field-ready view of the same record. Three critical states: ready → rejected → approved, with clear cause and retry path.

04

Storytelling layer

Created a narrative page that walks stakeholders through the journey before they open prototypes — actors, decisions, and experience principles.

05

Interactive prototypes

Four self-contained demos. Each one is a working HTML prototype that runs directly in the browser — no build step, no dependencies except the shared CSS foundation.

06

How it was shaped

Design

Semantic tokens over hardcoded values

Every color, spacing, and radius resolves to a CSS custom property. When PrimeNG components replace the HTML prototypes, the tokens map 1:1 to the design system — no visual regression.

:root {
  --primary: #1071E5;
  --ink: #303745;
  --canvas: #f6f8fb;
  --radius-md: 10px;
}
Prototype

HTML prototypes with real data

Pre-filled forms with realistic Salvadoran customs data — import companies, vehicle VINs, customs offices — so stakeholders immediately recognize the context.

Theme

Light / dark mode

Dark theme uses the same structural tokens with a night-blue canvas (#212630) and adjusted surface colors. Toggle persists across demos via localStorage.

Responsive

Mobile-first operational views

The boarding pass demo renders inside a phone chrome (390px) to simulate the field agent's actual device. The ARIVU flow scales to desktop admin screens.

07

Experience principles

"The right screen is not the one most full of data: it is the one that gives each actor the decision they need to make."
Continuity

ARIVU and boarding pass share the same record. No repeated information between office and field.

Operational clarity

States indicate what happened, why, and what the next action is — in the field, with gloves on, under sun.

Traceability

Every advance leaves an understandable log for the next person in the chain. Rejection is not an end state — it is a step with a path forward.
